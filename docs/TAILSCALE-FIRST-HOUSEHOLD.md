# Tailscale-first household onboarding — authoritative direction (9 November 2026)

This is **personal household software** for the owner and partner, for a sustained private alpha. Solve real daily use before creating account systems, websites, feature matrices, admin dashboards, monetization, or generalized member infrastructure. The fact that a future commercial direction might change the identity model is **not** permission to add those systems now.

**Normal owner-client experience:** install Bruiser/OptiPlex NOW on a supported Linux device; if Tailscale is running and the user is signed in, discover the existing OptiPlex; select/confirm the right server at most once; use already authorized services. If Tailscale is absent, offer the existing supported graphical installer or link to its official setup guide; if signed out, direct the user to its login. Existing client settings, credentials, paired Moonlight profiles, host files and Steam state survive updates. No second Bruiser login is desired.

**Service intent:**
- **Games:** Wolf/Moonlight is an internal detail, not an enrollment gate. On owner-approved devices, detect an already paired Moonlight identity and leave it alone; on a genuinely new one, orchestrate the supported Moonlight predefined-PIN ↔ host Wolf API handshake automatically and verify it. Keep separate NOW managed Games authorization until an independently secure Tailscale-based replacement is actually implemented and accepted. Never auto-approve an untrusted user or override Wolf's proof of possession.
- **Videos:** Use the existing host-validated Jellyfin discovery and open in a browser. Jellyfin's own account/session remains authoritative; do not create or distribute administrator tokens. Remove the needless reliance on a Games restricted SSH credential from *media discovery* only after replacing it with a host-verified, limited independent mechanism.
- **Files:** Existing regular SSH/SFTP works on owner machines and must be preserved. Do not enable Tailscale SSH (which can change tailnet-port-22 handling) or substitute Taildrive until tested explicitly and shown to simplify a real problem. The mere fact that two users share a Tailscale account does not justify giving every device host shell authority.
- **Downloads:** Preserve VPN isolation and owner-only native service operations. Host-local owner is independently valid, even without a Wolf or Games key. Remote Games/Downloads credentials must remain restricted and independently approved until replaced safely.
- **Music:** Preserve the already working household playback/authentication and don't use Wolf as a precondition.

**Household expansion:** Tailscale's native *share one machine by email* permits an external user to reach only the OptiPlex; invited users must receive separately approved *application* permissions. The partner's own Tailscale account is the preferred route (avoids shared credential recovery/revocation headaches). Tailscale network reachability is not automatic Jellyfin, Music, Files, Downloads, Steam or admin authority. No custom SMTP/MonumentRisk.com account portal is warranted now.

## Actual work merged into main (9 November 2026)

- [#296](https://github.com/SteezyMode/OptiplexNow/pull/296) — remove the erroneous GTK Games-key gate from host Downloads, delegating to existing host-local/restricted transport. Existing package/host/credentials unchanged by source merge.
- [#297](https://github.com/SteezyMode/OptiplexNow/pull/297) — on an empty first-run host config and a connected Tailscale session, automatically enumerate server candidates once. It still asks the user to select an intended host and does **not** create a device grant or silently trust any GameStream port.
- [#298](https://github.com/SteezyMode/OptiplexNow/pull/298) — package a **disabled-by-default** owner-only Moonlight CLI/Wolf PIN coordinator. Checks existing pairing first; new-pair flow requires an explicitly enabled, pinned-owner Tailscale Wolf broker; verifies response and refuses ambiguous or different-source requests. The GUI does not run it yet.

**Physical verification already completed:** On the actual Pop!_OS Mac mini, `tailscale status` reported Running; `moonlight list` confirmed paired; batch SFTP succeeded; Jellyfin `media-discover.py` printed available; OptiPlex v1.22.3 ran a Wolf container and had the host-local Downloads broker. Host owner and pinned-phone files existed with 0600 permissions. A **temporary** Tailscale-only broker accepted a Mac mini `prepare` request and returned `{"success":true,"status":"prepared"}`, verifying host-side owner identity and fresh-request baseline preparation. It did **not** complete a new Moonlight handshake. All existing devices were already paired. No existing keys, certificates, Wolf pairing state, Jellyfin, SSH, downloads/VPN or content were altered by these tests.

## Non-optional next acceptance and anti-duplication rules

1. **Keep this plan in `main`, linked from the repository README and product direction, not stranded in a draft PR.** Check merged work and existing installed host/client helpers before writing replacements. Treat [issue #295](https://github.com/SteezyMode/OptiplexNow/issues/295) as the continuation/acceptance tracker, not authorization to rebuild an entire membership system.
2. On an honestly unpaired new Linux client under the already pinned owner Tailscale identity, run the #298 backend with a temporary, source-authenticated Wolf broker. Confirm actual Moonlight PIN handshake, Wolf persistence across restart, Steam streaming with input, no manual Wolf UI, and clean denial for a non-owner node. Do **not** unpair any working machine just to manufacture this test.
3. Replace Wolf-coupled **Bruiser** enrollment with separately issued per-device server-side service credentials or narrow Tailscale-authenticated service grants. The owner experience should ultimately require no QR, copied code, Linux password, server terminal, or SSH authorization on routine client install; server authorization must not equate to merely being on Tailscale.
4. Jellyfin / Music / Downloads / Files must function independently of Wolf. Preserve service-native logins as needed. Once the actual first-run owner integration works, evaluate the smallest practical owner-management control for a separate household Tailscale user; do not assume household users should inherit owner's Steam workspace or host shell.
5. Record **source implemented vs CI passed vs shipped .deb vs physically verified** separately. Never call alpha setup complete because a test helper or partial code exists. All future edits must preserve currently working v1.22.3 behavior and provide rollback by immutable versioned release.

No cloud vendor portal, owner-email service, public endpoint, generic RBAC, OAuth, subscription model, local-folder migration or Taildrive/SFTP replacement is required for this household milestone.
