# OptiPlex NOW v1.19.0 Closed Beta

**Linux amd64 test prerelease for owner-managed Steam Games. NOT accepted Private Alpha 1 or a complete three-pillar installer.**

## Highlights

- NOW's Games button uses an authenticated, device-bound, restricted SSH broker to request a managed Wolf Steam lobby. Unlike the previous direct Steam application launch, the managed route keeps the physical host desktop independent and uses the existing approved owner Steam workspace.
- Starts Moonlight when needed, even if Wolf still reports an earlier UI session; observes Steam runner exit, closes NOW-owned Moonlight and attempts bounded lease reconciliation after a confirmed natural exit.
- The host policy now permits guarded reconciliation of a finished Steam lease while preserving exactly one residual Wolf UI session from the **same approved owner device**; it refuses foreign sessions, active lobbies and other Steam writers. The cleanup is non-mutating with respect to Wolf.
- Games controls use the compact single-window navigation introduced after v1.18.0, with restricted helper packaging and source/CI regression tests.

## Actual physical evidence (October 23, 2026)

On a Linux Mint XFCE MacBook client connected to an existing Pop!_OS NVIDIA OptiPlex, NOW's test build opened Moonlight and Steam Big Picture, streamed playable Resident Evil 2 Remake with working mouse and keyboard, and left the host desktop available. Exiting Steam closed the managed lobby and client stream; the revised host reconciliation archived its lease, and a subsequent natural-exit run returned `wolf_ui_connected` without a manual lease reset. A second Steam launch succeeded without restarting Wolf. The live host's reconciler was separately updated and tested. Game audio and controller input were not separately verified in this trial.

This evidence does **not** demonstrate fresh-install no-terminal enrollment, concurrent approved owner devices, enforced member roles, or a disposable clean-host install.

## Requirements for managed Games on an existing host

A compatible Wolf/Moonlight installation, **owner-enrolled device key**, narrowly configured host broker, explicit host approval, correct existing owner Steam workspace and single-writer protection. This Debian package supplies the **client**, not an automatic host-side broker deployment or enrollment. The previously released direct Steam shortcut is not a secure substitute for owner-authorized Games.

## Known issues and unaccepted scope

- Wolf UI is briefly visible before/after Steam; on one test Steam initially appeared minimized or behind another window. One RE2-to-Steam exit took approximately one minute.
- Native Wolf/Moonlight pairing and existing host adoption still require manual owner steps. Automatic recovery across all interruptions and reboot states is unaccepted.
- Videos currently need a configured Jellyfin address rather than authenticated no-URL discovery; managed Jellyfin installation is unfinished.
- Downloads and file management are not yet integrated as an owner-only, VPN-kill-switch-verified workflow. Existing reference host services were manually configured.
- No separate viewer/member privileges, full graphical three-service setup, Windows builds, or 15-minute fresh-host acceptance.
- The host's administrative Steam and Wolf data must not be overwritten by a beta test. Do not run the clean-host pilot installer against a functioning Wolf host.

## Package validation and rollback

Download `OptiPlex-Now_1.19.0_amd64.deb` and `SHA256SUMS` from this tagged release, verify SHA256 and Debian package metadata, then install on a supported Linux client. For an existing-host rollback use the prior immutable v1.18.0 package while preserving client config, Moonlight identity, host SSH keys and existing host-side policies. Rolling back the client does not roll back host broker changes.
