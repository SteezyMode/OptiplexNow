# OptiPlex NOW v1.20.0 Closed Beta

**Linux amd64, existing-host owner testing. This is NOT accepted Private Alpha 1 or a turnkey three-pillar host installer.**

## What changed since v1.19.0

- Owner Downloads: embedded VueTorrent UI and read-only/download-queue integration against supported existing host services, with guarded connection checks. Search/plugin provisioning, reliable destination selection, file organization and VPN fail-closed verification are **not** fully accepted.
- More explicit Host Setup diagnostics and protected/opt-in host provisioning/adoption paths. The separate Wolf-only clean-host installer is **experimental** and must not be run on an existing working Wolf system.
- Stronger restricted owner-device enrollment: private Tailnet HTTP staging, signed Moonlight-certificate proof checked against host-owned Wolf pairing, independently pinned owner iPhone approval and replay denial. Source and offline HTTP integration tests pass; reference-host pilot must still be started explicitly.
- Already-authorized restricted clients now short-circuit duplicate QR requests after their existing host Games status command succeeds. A failed/offline check never automatically grants approval.
- Additional GTK, launcher/process, network, download and security checks plus incremental C modularization and executable regression tests.

## Verified versus not verified

- **CI:** 484 Python tests on the previous approved development snapshot, native sanitizer checks, full Debian build and GTK smoke tests passed. The release workflow repeats source-build and package validation before publishing.
- **Physically verified October 26:** the owner OptiPlex accepted an isolated pinned QR pilot deployment and non-listening preflight. A Tailscale-connected iPhone reached the host-local approval page and retrieved a verified Wolf device identity. Approval was denied, as intended, for a restricted SSH key **already authorized** to that identity; the same fingerprint and Wolf ID recurred on retry. An expired pending request was later observed. **No successful new credential authorization or wrong-phone denial has yet been physically demonstrated.**
- **Earlier physical evidence:** reference OptiPlex + Mac mini/Mint clients streamed real Wolf Steam gameplay with the host desktop independent, and Jellyfin/VueTorrent worked with owner-configured services. This is not equivalent to a clean supported host/client install.

## Boundaries and known alpha blockers

- Device setup still needs preexisting, trusted Tailscale and Wolf/Moonlight pairing. Host-side QR enrollment is disabled unless deliberately started by the host owner; the client `.deb` **does not** enable a server listener or modify `authorized_keys`.
- **Wolf pairing is not NOW owner authorization.** Direct Wolf-published Steam remains accessible to paired clients separately from restricted NOW Games/Downloads grants (issue #192); do not advertise single unified security until resolved.
- Automatic, authenticated zero-URL Jellyfin discovery and managed media installation, full downloader VPN egress and kill-switch, owner file-management boundary, search plugins, first-run experience and disposable clean-host installation remain unaccepted.
- One owner with owner-operated devices only. No member/viewer isolation, Windows host/client package, or 15-minute clean-install claim.
- Owner's live Wolf/Steam, SSH keys, Jellyfin data, VPN and Tailscale state must be preserved; do not test host provisioning by overwriting an adopted working system.

## Download and rollback

Download `OptiPlex-Now_1.20.0_amd64.deb` and `SHA256SUMS` from this immutable prerelease. Verify checksums and Debian metadata; install only on a supported Debian/Ubuntu-derived Linux client. Settings and local Moonlight identities should persist across upgrades. The [v1.19.0 prerelease](https://github.com/SteezyMode/OptiplexNow/releases/tag/v1.19.0) is the last published rollback package. Downgrading the client does **not** roll back separately installed host enrollment pilots or host policy changes.
