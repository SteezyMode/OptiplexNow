# OptiPlex NOW v1.21.0 — Friends & Family Closed Beta

**Linux amd64 client for an existing, owner-prepared entertainment server.** The name OptiPlex NOW remains an internal development codename. This is not a turnkey server installer or a claim that all Private Alpha 1 acceptance tests passed.

## Download and install

Use the release asset **OptiPlex-Now_1.21.0_amd64.deb** on Linux Mint, Pop!_OS or supported Ubuntu-family amd64 clients. Open it with the desktop package installer; existing users may upgrade over the earlier client. Verify the published `SHA256SUMS` if installing manually. This package does **not** change the OptiPlex host.

## Changes since v1.20.0

- Main navigation includes a permanent Dashboard tab and active page indication.
- Downloads now separates **Transfers** (default) and **Search**. Transfers refreshes approximately every three seconds while visible, and reports transfer progress, speed, ETA and seeds.
- Owner-only transfer controls are submitted through the existing restricted SSH device broker: pause/resume, reannounce, recheck and remove. **Remove always retains downloaded files** and asks for confirmation.
- Search supports larger paginated results. Search currently still waits up to twelve seconds before showing results; incremental display is not part of this release.
- Download destination confirmation follows the selected folders. Advanced VueTorrent remains available inside Downloads.
- VPN health pill reports owner-authorized Gluetun status and shared network attachment, with last-check details and a conditional AirVPN account link. **Healthy is not proof that kill-switch behavior has been independently tested during an outage.**
- Fixes the previously observed GTK destination-chooser crash and poor search-result contrast.

## For the host owner

**Host compatibility must be checked before using the new native Transfers actions.** The host needs the matching read-only queue/status and restricted owner-download management modules. Merely installing this client will not update the server. Deploy host files deliberately, back up existing modules, verify restricted key authorization and do not restart unrelated Docker services. A host with only v1.20-era modules may show an unavailable native queue.

This beta targets a **single, already configured server**, with owner-assisted client enrollment. All downloading and management operations remain owner-only. Family/friends without owner-device authorization should use only services they are explicitly permitted to access.

Wolf pairing itself authorizes access to published Wolf apps independently of NOW's restricted owner broker. **Do not pair an untrusted guest** to a Wolf app catalog containing the owner's Steam session. Tailscale admission also does not by itself authorize the NOW owner service.

## Verification and known gaps

- The integrated PR #215 passed its Python, GTK/package and native sanitizer CI checks before merge; the tagged release publisher also builds and tests from source before attaching a Debian package.
- Previous real-device testing covered NOW Games, Jellyfin and the earlier Downloads search/add workflow on the owner's configured hardware. **The refreshed v1.21.0 Transfers UI, management actions and fresh-client onboarding still require a specific physical acceptance pass after release.**
- A clean host setup wizard, successful brand-new QR device approval, one-click new-family-device onboarding, and simulated VPN kill-switch outage have not been physically accepted. This release does not grant members access to owner-only downloads or Steam account management.
- Rollback: reinstall a prior immutable tagged .deb; preserve existing NOW/Moonlight pairing identities and settings. Do not delete those credentials to test a clean profile.

**This release is for limited, owner-approved household testing, not public general deployment.**
