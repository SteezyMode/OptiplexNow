# OptiPlex NOW v1.21.14 — Current Alpha

This update hardens the owner-managed Games flow after an interrupted Steam
launch. It keeps the Downloads improvements, native GTK folder chooser, media
access, VPN checks and other v1.21.13 features.

## Games: recover abandoned launches safely

- A timed-out or interrupted Wolf Create/Join can leave a durable Steam
  lease in `creating`, `created` or `uncertain` state. This protects
  against duplicate Steam launches and **remains intentional**.
- When the **same already-approved owner device** explicitly launches Games,
  the client can now resolve an abandoned transaction if the host verifies
  **zero Wolf lobbies, zero Wolf sessions, and no running Steam writer**,
  then rechecks Wolf immediately before privately archiving the old lease.
- Games Settings now has **Recover Idle Games Session**, which invokes that
  same restricted owner-only check asynchronously. It never uses regular
  administrator SSH, resets enrollment, stops Wolf, or changes Steam files.
- If verification fails or anything might still be active, the lease is
  preserved. Recovery refusals are labelled as an interrupted session
  needing review, not incorrectly reported as lost owner approval.
- The existing `joined` lease recovery continues to allow only the
  same owner's residual Wolf UI and otherwise rejects activity. Older
  legacy v1 leases still require local operator review.

## Source of the fix

On the reference host, a v2 `uncertain` Steam lease survived a Wolf
restart even though Wolf reported zero lobbies and sessions and the host's
Steam writer census was clear. The restricted owner key was still valid.
A verified local operator recovery archived the record successfully. This
release makes the same safety proof available to the approved owner client.

## Installation and limitations

- Install the v1.21.14 `.deb` on **both the client and the host**.
  The visible Games Settings button lives in the client; the guarded
  recovery logic runs in the already approved packaged host broker.
- If `owner-host-upgrade.py --check` reports `up_to_date`, **do not**
  repeat the broker migration; package updates carry the new trusted code.
- No live server or owner credentials are changed by publication. The
  installer itself never edits SSH authorized keys, Moonlight pairing,
  Steam libraries, Docker mounts or VPN routing.
- Host-independent privileged Wolf users could still race during snapshots;
  upstream Wolf admission needs its own enforcement. This is a
  fail-closed alpha recovery, **not** proof that all Steam failures disappear.
- Verified in isolated automated Python owner-policy/lease tests, native
  GTK integration guards, sanitizers, and installed-package smoke tests.
  No destructive interrupted-Create test was performed on the live owner host.

Previous v1.21.13 artifacts and checksums remain available for rollback.
