# Bruiser / OptiPlex NOW v1.22.1 — Private Alpha maintenance

This patch updates v1.22.0 without changing the approved host stack.

## Fix: Discover → Tracks

- Fixes the **Tracks** / **View Tracks** action on Discover album cards and artist discography albums.
- The button already selected a MusicBrainz release-group ID and constructed the album context correctly, but the GTK client incorrectly passed OpenSubsonic-only `--auth-format=form` to the DroppedNeedle REST helper. The helper's argument parser rejected the invocation before sending the track-list request.
- The native client now invokes the authenticated, device-scoped REST helper using its supported `--format=rows` option. No music playback password is exposed to this helper, and simply viewing a track list never requests or downloads music.
- A more precise error appears if the track list genuinely cannot be loaded. Regression tests cover the exact helper CLI shape, decoded track-list rows, read-only GET, and existing per-song request behavior.

## Unchanged

Discover remains the default Music landing page; Home is hidden. Your Library, albums, artists, playlists, playback, Likes, explicit Add Song/Add to Library actions, album covers and all other Bruiser features remain unchanged. The separate, already-installed DroppedNeedle artwork resolver v3 is untouched. The `.deb` does not modify the home server or its Docker image.

## Release

The GitHub Actions release pipeline builds and signs off an immutable `OptiPlex-Now_1.22.1_amd64.deb`, updates the rolling `OptiPlex-Now_amd64.deb`, and publishes `SHA256SUMS` only after full source, package, and integration/smoke checks succeed. Local reference-hardware verification of Tracks is still required after installation.

This remains an owner-operated **Private Alpha** milestone, not a public general-availability declaration.
